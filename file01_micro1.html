Slide #1

📌 อะไร (What):
หน้าปกบทเรียนวิชา 113301 Microprocessor Engineering Lecture 1: การแนะนำระบบฝังตัว (Embedded System) และการทบทวนการออกแบบวงจรตรรกะดิจิทัล (Part I)

⚙️ ยังไง (How):
แบ่งเนื้อหาออกเป็น 2 ส่วนหลัก: 1) นิยามสถาปัตยกรรมระบบฝังตัว 2) ทบทวนวงจรตรรกศาสตร์ Combinational/Sequential และวงจร Register Transfer

Slide #2

📌 อะไร (What):
คำถามนำเข้าสู่บทเรียน: What is an embedded system? (ระบบฝังตัวคืออะไร?)
❓ ทำไม (Why):
กระตุ้นให้นักศึกษาตั้งคำถามและแยกแยะความแตกต่างระหว่างคอมพิวเตอร์ทั่วไป (PC) กับระบบฝังตัว
⚙️ ยังไง (How):
สังเกตจากอุปกรณ์รอบตัวที่มีไมโครโปรเซสเซอร์หรือไมโครคอนโทรลเลอร์ซ่อนอยู่ภายในเพื่อควบคุมฟังก์ชันเฉพาะอย่าง
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
Embedded System คือ ระบบประมวลผลคอมพิวเตอร์ขนาดเล็กที่ถูกออกแบบฝังไว้ภายในอุปกรณ์ เพื่อทำหน้าที่ควบคุมการทำงานเฉพาะอย่าง (Application-Specific Control) ของอุปกรณ์นั้นๆ โดยที่ผู้ใช้ไม่ได้มองว่ามันเป็นคอมพิวเตอร์ทั่วไป

Slide #3

📌 อะไร (What):
คำถามขยายความ: What is an embedded system?
❓ ทำไม (Why):
ชี้ให้เห็นขอบเขตที่ครอบคลุมของระบบฝังตัวในอุปกรณ์รอบตัว
⚙️ ยังไง (How):
วิเคราะห์ระบบฝังตัวในอุปกรณ์ เช่น เครื่องซักผ้า รถยนต์ สมาร์ตทีวี ไมโครเวฟ อุปกรณ์อิเล็กทรอนิกส์ทางการแพทย์ และระบบวัดทางอุตสาหกรรม
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
ระบบฝังตัวต่างจาก PC ตรงที่ไม่มีอินเทอร์เฟซคีย์บอร์ด/จอภาพเต็มรูปแบบ แต่เน้นการเชื่อมต่อกับเซนเซอร์ (Sensors) เพื่ออ่านค่าสภาวะ และส่งสัญญาณควบคุมตัวกระตุ้น (Actuators) แบบ Real-time

Slide #4

📌 อะไร (What):
นิยามเชิงสรุปของระบบฝังตัว (Embedded System Definition):
- Tiny computer, Hidden Control
- A system whose principal function is not computational, but which is controlled by a computer embedded within it.
❓ ทำไม (Why):
เพื่อเป็นคำนิยามมาตรฐานทางวิศวกรรมที่ใช้ในการสอบและอ้างอิงทางวิชาการ
⚙️ ยังไง (How):
จำจำกัดความ 2 ข้อหลัก: 1) ขนาดเล็กและถูกซ่อนการทำงาน 2) หน้าที่หลักไม่ใช่การประมวลผลคำนวณทั่วไป แต่เป็นการควบคุมอุปกรณ์อื่น
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
คุณลักษณะเด่นของระบบฝังตัวคือ มีทรัพยากรจำกัด (RAM/ROM/Power ต่ำ) มีราคาถูก ทนทาน และทำงานเฉพาะทางได้อย่างเสถียรตลอด 24 ชั่วโมง

Slide #5

📌 อะไร (What):
แผนผังบล็อกสถาปัตยกรรมของระบบฝังตัว (Embedded System Architecture)
❓ ทำไม (Why):
แสดงองค์ประกอบฮาร์ดแวร์พื้นฐานที่จำเป็นทุกส่วน
⚙️ ยังไง (How):
ประกอบด้วย 1) Processor (CPU), 2) Memory (Flash ROM & SRAM), 3) Input Ports (Sensors/Buttons), 4) Output Ports (LEDs/Motors/Displays) และ 5) Clock System
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
องค์ประกอบที่สำคัญที่สุดคือตัวประมวลผล (Processor) ซึ่งทำหน้าที่อ่านรหัสโปรแกรมจาก Memory มาควบคุมพอร์ต I/O

Slide #6

📌 อะไร (What):
การเปรียบเทียบ CISC vs RISC:
• CISC: Complex Instruction Set Computer
• RISC: Reduced Instruction Set Computer
❓ ทำไม (Why):
เข้าใจปรัชญาการออกแบบสถาปัตยกรรมตัวประมวลผล
⚙️ ยังไง (How):
CISC มีคำสั่งจำนวนมาก ซับซ้อน ใช้หลาย Clock ต่อคำสั่ง ส่วน RISC มีคำสั่งขนาดเล็ก เท่ากัน ทำงานเร็วใน 1 Clock Cycle เป็นรากฐานของไมโครคอนโทรลเลอร์ AVR/ARM
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
คำถามสอบบ่อย: สถาปัตยกรรมแบบใดเหมาะกับ Embedded System มากกว่า? คำตอบคือ RISC เพราะมีโครงสร้างฮาร์ดแวร์เรียบง่าย ประหยัดพื้นที่ชิป ใช้พลังงานต่ำ และทำงานรวดเร็วคาดเดาเวลาได้แม่นยำ (Deterministic Timing)

Slide #7

📌 อะไร (What):
ประเภทหน่วยความจำ: Volatile Memory vs Non-Volatile Memory
❓ ทำไม (Why):
เพื่อจัดสรรการใช้งานหน่วยความจำในไมโครคอนโทรลเลอร์ให้ถูกต้อง
⚙️ ยังไง (How):
Volatile (เช่น RAM) ข้อมูลสูญหายเมื่อดับไฟ ใช้เก็บตัวแปรชั่วคราว ส่วน Non-Volatile (เช่น ROM/Flash) ข้อมูลคงอยู่แม้ไม่มีไฟ ใช้เก็บโค้ดโปรแกรม (Firmware)
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
ในไมโครคอนโทรลเลอร์ เช่น ATmega328P จะใช้ Flash Memory (Non-volatile) ขนาด 32 KB เก็บโค้ด และใช้ SRAM (Volatile) ขนาด 2 KB เก็บตัวแปรขณะทำงาน
สไลด์ที่ 8 จาก 52

Slide #8

📌 อะไร (What):
วงรอบการประมวลผลคำสั่งของซีพียู (Processor Program Execution)
❓ ทำไม (Why):
อธิบายกลไกการทำงานของ CPU ในการรันซอฟต์แวร์
⚙️ ยังไง (How):
1. Fetch: อ่านรหัสคำสั่งจาก Memory ที่ระบุโดย Program Counter (PC)
2. Decode: ถอดรหัสคำสั่งใน IR
3. Execute: ประมวลผลและเพิ่มค่า PC
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
วงรอบ Fetch-Decode-Execute ทำงานต่อเนื่องด้วยจังหวะสัญญาณนาฬิกา (Clock Signal)
สไลด์ที่ 9 จาก 52

Slide #9

📌 อะไร (What):
การจัดโครงสร้างหน่วยความจำและบัส: (a) Von Neumann vs (b) Harvard
❓ ทำไม (Why):
เปรียบเทียบสถาปัตยกรรมบัสของซีพียูในการอ่านคำสั่งและข้อมูล
⚙️ ยังไง (How):
Von Neumann ใช้บัสร่วมกัน ทำให้เกิดคอขวด ส่วน Harvard แยกบัส Program และ Data ออกจากกัน ทำให้ประมวลผลได้เร็วขึ้น
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
สถาปัตยกรรม Harvard เหมาะสำหรับโปรเซสเซอร์ RISC ความเร็วสูงเพราะสามารถ Fetch คำสั่งถัดไปพร้อมกับ Execute อ่านเขียน Data ใน Memory ได้ในจังหวะ Clock เดียวกัน
🔌 แผงจำลองการไหลของข้อมูล Von Neumann vs Harvard (SVG Animation)

Memory Map ช่วยให้ผู้เขียนภาษา Assembly ทราบตำแหน่งที่อยู่ที่แน่นอนของตัวแปรและรีจิสเตอร์พอร์ต I/O

Slide #11

📌 อะไร (What):
ความแตกต่างระหว่าง Microprocessor และ Microcontroller
❓ ทำไม (Why):
เลือกชิปประมวลผลให้เหมาะกับความต้องการของระบบ
⚙️ ยังไง (How):
Microprocessor มีเฉพาะ CPU ต้องต่อชิปภายนอก ส่วน Microcontroller มี CPU, RAM, ROM, I/O รวมอยู่บนชิปเดียว
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
Microcontroller เหมาะสำหรับระบบฝังตัวเพราะเป็นระบบสมบูรณ์ในชิปเดียว (System-on-Chip) ทำให้บอร์ดมีขนาดเล็กและต้นทุนต่ำ

Slide #12

📌 อะไร (What):
การเปรียบเทียบข้อดีข้อเสียระหว่าง Microprocessor vs Microcontroller
❓ ทำไม (Why):
ประเมินต้นทุน ขนาด และความซับซ้อนของบอร์ดวงจร
⚙️ ยังไง (How):
Microprocessor มีประสิทธิภาพคำนวณสูง ขยายระบบง่าย แต่บอร์ดซับซ้อนกินไฟสูง ส่วน Microcontroller ขนาดเล็ก ประหยัดไฟ แต่ขยายระบบได้จำกัด
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
ระบบฝังตัวส่วนใหญ่กว่า 90% เลือกใช้ Microcontroller เนื่องจากตอบโจทย์เรื่องขนาด พลังงาน และราคา

Slide #13

📌 อะไร (What):
พอร์ตการสื่อสารข้อมูล: Parallel Port vs Serial Port
❓ ทำไม (Why):
เข้าใจรูปแบบการต่อรับส่งสัญญาณระหว่างโปรเซสเซอร์กับอุปกรณ์ภายนอก
⚙️ ยังไง (How):
Parallel ส่งข้อมูลหลายบิตพร้อมกันผ่านบัสหลายเส้น ส่วน Serial ส่งทีละบิตผ่านสายไฟเส้นเดียว
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
Parallel ส่งได้เร็วแต่ใช้สายไฟเยอะเกิดสัญญาณรบกวน Cross-talk ส่วน Serial ประหยัดพอร์ต และส่งได้ระยะไกลกว่า

เลือกข้อมูลจากรีจิสเตอร์เพียง 1 ตัวขึ้นสู่บัสร่วม
⚙️ ยังไง (How):
ใช้ MUX ขนาด 4-to-1 หรือ 8-to-1 ดึงข้อมูลจาก R0..R7 ออกบัส
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
สายเลือก Source Select กำหนดที่อยู่รีจิสเตอร์ต้นทาง
สไลด์ที่ 46 จาก 52

Slide #46

📌 อะไร (What):
การต่อ 8-to-1 Multiplexer จาก 4-to-1 MUXes สองตัว (ไอซี SN74251)
❓ ทำไม (Why):
เพื่อรองรับการเลือกรีจิสเตอร์ต้นทาง 8 ตัว (R0..R7)
⚙️ ยังไง (How):
ใช้ 4-to-1 MUX 2 ตัว ร่วมกับสายเลือก S2 ควบคุมขา Enable สลับกัน
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
เป็นโครงสร้างไอซีสำเร็จรูป SN74251
สไลด์ที่ 47 จาก 52

Slide #47

📌 อะไร (What):
การควบคุมเอาต์พุตปลายทาง (Output Control for Register Transfer)
❓ ทำไม (Why):
ป้องกันไม่ให้รีจิสเตอร์ปลายทางตัวอื่นถูกเขียนทับ
⚙️ ยังไง (How):
ส่ง Clock Pulse ให้เฉพาะรีจิสเตอร์ปลายทางที่ถูกเลือกเท่านั้น
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
สายบัสป้อนข้อมูลรอที่ขา D ของทุกตัว แต่มีเพียงตัวที่ได้ Clock ที่จะบันทึก
สไลด์ที่ 48 จาก 52

Slide #48

📌 อะไร (What):
วงจร 2-to-4 Demultiplexer (Decoder) สำหรับเลือกปลายทาง
❓ ทำไม (Why):
ถอดรหัสสายเลือก Destination ไปยิง Clock ให้รีจิสเตอร์เป้าหมาย
⚙️ ยังไง (How):
รับสาย SEL0, SEL1 และ ENABLE เปิดเอาต์พุต 1 ใน 4 สาย
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
Demultiplexer ทำหน้าที่กระจายสัญญาณ Clock
สไลด์ที่ 49 จาก 52

Slide #49

📌 อะไร (What):
ตารางการทำงานของ 2-to-4 Demultiplexer
❓ ทำไม (Why):
แสดงสภาวะการถอดรหัสเลือกสายเอาต์พุต
⚙️ ยังไง (How):
เมื่อ Enable=1 เอาต์พุตสายที่ตรงกับค่า SEL1, SEL0 จะกลายเป็น 1
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
เมื่อ Enable=0 เอาต์พุตทุกสายจะเป็น 0 ป้องกันการจ่าย Clock
สไลด์ที่ 50 จาก 52

Slide #50

📌 อะไร (What):
การขยายเป็น 3-to-8 Demultiplexer จาก 2-to-4 Demultiplexers สองตัว
❓ ทำไม (Why):
เพื่อรองรับการเลือกรีจิสเตอร์ปลายทาง 8 ตัว (R0..R7)
⚙️ ยังไง (How):
ใช้ SEL0, SEL1 ป้อนเข้าทั้งสองตัว และใช้ SEL2 สลับ Enable ระหว่างชิปบนและล่าง
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
สามารถควบคุมเลือกรีจิสเตอร์ปลายทางได้สูงสุด 8 ตัว
สไลด์ที่ 51 จาก 52

Slide #51

📌 อะไร (What):
วงจรสมบูรณ์ของการย้ายข้อมูลระหว่างรีจิสเตอร์ผ่านบัส (The Final Register Transfer Circuit)
❓ ทำไม (Why):
แผนผังระบบบัสและการย้ายข้อมูล 1 บิตสมบูรณ์ที่เป็นหัวใจของ CPU
⚙️ ยังไง (How):
8-to-1 MUX เลือกต้นทางขึ้นบัส + 3-to-8 Decoder ยิง Clock ให้ปลายทาง
💡 เฉลยคำตอบประเด็นประจำสไลด์ (Slide Answer):
นี่คือสถาปัตยกรรม Common Data Bus ที่ออกสอบบ่อยที่สุด!

เชื่อมโยงความรู้พื้นฐานดิจิทัลไปสู่การสร้าง CPU 8-bit เต็มรูปแบบ

ข้อที่ 1: (สไลด์ 45-46) ทำไมการเลือกสายสัญญาณจากรีจิสเตอร์ต้นทาง (R0..R7) ขึ้นสู่ Common Data Bus จึงต้องใช้ Multiplexer?

ก. เพื่อทำหน้าที่เป็นสวิตช์เลือกเปิดทางข้อมูลจากรีจิสเตอร์เพียง 1 ตัวขึ้นสู่บัสโดยไม่เกิดการชนกันของสัญญาณ
ข. เพื่อจ่ายสัญญาณ Clock ให้กับรีจิสเตอร์ปลายทาง
ค. เพื่อกลับค่าบิตข้อมูลก่อนบันทึก

ข้อที่ 2: (สไลด์ 36) ทำไมการเลื่อนบิตไปทางซ้าย (Shift Left) 1 บิตใน binary จึงเท่ากับการคูณด้วย 2?

ก. เพราะค่าน้ำหนักประจำหลัก (Weight) ของเลขฐานสองเพิ่มขึ้น 2 เท่าในทุกๆ ตำแหน่งที่ขยับไปทางซ้าย
ข. เพราะการ Shift Left จะตัดบิต LSB ทิ้งเสมอ

ข้อที่ 3: (สไลด์ 27) การประยุกต์ใช้กฎ DeMorgan แปลงวงจรเป็น NAND Gate ชนิดเดียว มีข้อดีอย่างไรต่อกระบวนการผลิตฮาร์ดแวร์?

ก. ลดจำนวนชิป IC เหลือเพียงเบอร์เดียว (7400 NAND) ประหยัดต้นทุน Socket Cost และง่ายต่อการคลังอะไหล่
ข. เพิ่มความเร็วสัญญาณนาฬิกาของซีพียูเป็น 2 เท่า
